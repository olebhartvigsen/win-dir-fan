# Hide FanFolder from Alt+Tab: Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Remove FanFolder's main window from the Windows Alt+Tab switcher while keeping its taskbar button fully functional (click to toggle the fan, DWM icon thumbnail on hover).

**Architecture:** The main window (`MainWindow.cpp`) currently uses `WS_OVERLAPPEDWINDOW` with extended style `0`, deliberately avoiding `WS_EX_TOOLWINDOW` so it gets a real taskbar button. That same non-tool-window status is what makes Windows include it in Alt+Tab. The fix is to add `WS_EX_TOOLWINDOW` (which removes the Alt+Tab entry) and then explicitly re-insert the taskbar button via `ITaskbarList::AddTab()` (which works on tool windows). This is the canonical pattern tray-toggle utilities have used since Windows 7.

**Tech Stack:** Win32/C++, COM (`ITaskbarList` from `shobjidl.h`), DWM thumbnail API, GitHub Actions CI (Windows 2022, MSVC, CMake).

## Current state (what makes FanFolder appear in Alt+Tab)

### MainWindow creation (`FanFolder/src/MainWindow.cpp:140-152`)

```cpp
bool MainWindow::Create() {
    _hwnd = CreateWindowExW(
        0,                                    // <-- no WS_EX_TOOLWINDOW = appears in Alt+Tab
        ClassName(), L"FanFolder",
        WS_OVERLAPPEDWINDOW | WS_MINIMIZE,
        -32000, -32000, 1, 1,
        nullptr, nullptr, _hInst, this);

    if (!_hwnd) return false;

    // Make it a taskbar button by NOT using WS_EX_TOOLWINDOW
    // Show minimised in taskbar
    ShowWindow(_hwnd, SW_SHOWMINNOACTIVE);
```

The comment at line 150 is the smoking gun: the tool-window style was avoided specifically to get the taskbar button. But a top-level visible window without `WS_EX_TOOLWINDOW` always shows in Alt+Tab. A minimized `WS_OVERLAPPEDWINDOW` is still "visible" for Alt+Tab purposes.

### FanWindow (already correct, no change needed)

```cpp
// FanFolder/src/FanWindow.cpp:164-168
_hwnd = CreateWindowExW(
    WS_EX_LAYERED | WS_EX_NOACTIVATE | WS_EX_TOPMOST | WS_EX_TOOLWINDOW,
    ClassName(), L"", WS_POPUP, ...);
```

The fan popup already has `WS_EX_TOOLWINDOW`, so it never appears in Alt+Tab. Only the main window leaks.

### Taskbar click trigger (`MainWindow.cpp:952-980`)

```cpp
case WM_SYSCOMMAND: {
    WPARAM cmd = wParam & 0xFFF0;
    if (cmd == SC_RESTORE) {
        self->ToggleFan();      // <-- taskbar click = toggle
        return 0;
    }
    if (cmd == SC_MINIMIZE) {
        self->ToggleFan();
        PostMessageW(hwnd, WM_MAIN_SHOW_MIN, 0, 0);
        return 0;
    }
```

Clicking the taskbar button sends `SC_RESTORE` (or `SC_MINIMIZE`), which routes into `ToggleFan()`. This stays unchanged.

### Destructor (`MainWindow.cpp:122-138`)

```cpp
MainWindow::~MainWindow() {
    RemoveTrayIcon();
    UninstallHooks();
    if (_hookThread.joinable()) { ... }
    if (_hwnd) { KillTimer(_hwnd, TIMER_ID_VDM_RECONCILE); }
    if (_vdm) { _vdm->Release(); _vdm = nullptr; }
    s_instance = nullptr;
}
```

Needs a new cleanup step for the `ITaskbarList` interface (delete the tab, release).

### Class members (`MainWindow.h:43-103`)

The `_vdm` member (`IVirtualDesktopManager*`) at line 79 is the existing pattern for holding a COM interface on the class. The new `ITaskbarList*` follows the same pattern.

### COM availability

- `OleInitialize(nullptr)` is called in `main.cpp:77`, so COM is already initialized.
- `shobjidl.h` is included in `pch.h:41`, so `ITaskbarList`, `IID_ITaskbarList`, and `CLSID_TaskbarList` are available with no new include.
- `CoCreateInstance` is already used for `CLSID_VirtualDesktopManager` (`MainWindow.cpp:183`), `CLID_FileOpenDialog` (`MainWindow.cpp:702`), and `CLSID_ShellLink` (`FileService.cpp`).


**Edit 2** - after `ShowWindow` (line 152) and before the DWM attributes (line 154), insert the taskbar registration:

```cpp
    // With WS_EX_TOOLWINDOW the window no longer gets an automatic taskbar
    // button.  Register one explicitly via ITaskbarList so the user still
    // has a clickable button that sends SC_RESTORE -> ToggleFan.
    if (SUCCEEDED(CoCreateInstance(CLSID_TaskbarList, nullptr,

                                   IID_PPV_ARGS(&_taskbar)))) {
        if (SUCCEEDED(_taskbar->HrInit())) {
            _taskbar->AddTab(_hwnd);
        } else {
            _taskbar->Release();
            _taskbar = nullptr;
        }
    }
```

Keep `ShowWindow(_hwnd, SW_SHOWMINNOACTIVE)` and all the DWM `DwmSetWindowAttribute` calls exactly as they are (lines 154-159). They work on any window style.

## Risks and tradeoffs

1. **`AddTab` click semantics on a tool window.** The canonical `ITaskbarList::AddTab` pattern works for "no taskbar button wanted, add to taskbar manually" scenarios. For a tool window that wants a real clickable taskbar button, `AddTab` should produce the same `SC_RESTORE`/`SC_MINIMIZE` messages that the non-tool window got. But the only proof is live on the desktop. If `AddTab` does not produce clickable behavior, the fallback is the existing tray icon (already wired to `ToggleFan` at `MainWindow.cpp:1083`), at the cost of losing the visible taskbar entry.

2. **`AddTab` click semantics variability.** Some references suggest `AddTab` only registered the button as a placeholder, and the window needed to be `SW_SHOWNORMAL`-visible to get proper click handling. The main window is `SW_SHOWMINNOACTIVE`, which may or may not satisfy that. If the button is present but non-clickable, the fix is to call `SetActiveAlt` / register as an active tab, or to briefly show the window `SW_SHOWNORMAL` before re-minimizing (similar to what the current `SC_RESTORE` handler intentionally avoids). This is a follow-up step if the basic approach does not fully work.

3. **DWM thumbnail may stop rendering.** `DWMWA_FORCE_ICONIC_REPRESENTATION` is set unconditionally and should work on a tool window, but this needs live verification.

4. **Virtual-desktop reconciliation.** `_vdm` reconciliation uses `MoveWindowToDesktop(_hwnd, ...)` which should be style-independent. Low risk but worth verifying (step 8).

5. **Layout is untouched.** The diff should show zero changes to `FanWindow.cpp` or any layout constant. If the user reports a visual regression, it is a regression in the deployment or an unrelated issue, not this change.
